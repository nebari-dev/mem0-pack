| mem0 REST subset behind the allowlist | new | mem0-pack | Tapas gateway pods (and any caller the NetworkPolicy admits) | `image/tests/test_allowlist.py`, `image/tests/test_serve.py`, `image/smoke.sh` (allowlist section) | Promises: with the admin key (`X-API-Key`), only `POST /memories` (add), `GET /memories` (list), `GET /memories/{id}`, `DELETE /memories/{id}` and `POST /search`; `/healthz` and `/readyz` need no key. Scope rule: `user_id` is required on add, list and search; `agent_id` and `run_id` only narrow; scope values are literal non-empty strings, never `*`; search takes no logical or operator filters; an add takes a top-level `user_id` and rejects a `filters` key. Errors: 404 with body `{"detail":"Not Found"}` for anything not allowlisted (`/auth/*`, `/configure`, `/reset`, and the rest); 401 without a valid key; 400 for an unscoped add, list or search; mem0's own 4xx/5xx otherwise. Caveat: `GET /memories/{id}` answers 200 with `null` for an id that does not exist, and mem0 does not check ownership on by-id calls (get, delete), so callers must verify the memory belongs to the person before acting on it. |
